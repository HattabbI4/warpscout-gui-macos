# Правила выпуска WarpScout для macOS

- Отправка тега `vX.Y.Z` запускает CI, подпись ZIP для Apple Silicon и Intel и публикацию стабильного GitHub Release. Отправляйте релизный тег или меняйте существующий тег только по явной просьбе пользователя выпустить релиз.
- До создания тега обновите `CFBundleShortVersionString` и увеличьте `CFBundleVersion` в `Resources/Info.plist`. Отправьте проверенный коммит в основную ветку.
- Используйте Conventional Commits (`feat:`, `fix:`, `build:`, `ci:`, `docs:`, `test:`). Генератор включает изменения `docs:` в список, если в релизе только документация. При изменении интерфейса обновляйте русские и английские строки в `Resources/*.lproj/Localizable.strings`.
- Создавайте аннотированный тег с темой `vX.Y.Z`. Пустое тело включает автоматические примечания. Для ручных примечаний добавьте второй аргумент `-m` с текстом. Общий текст получит маркер `changelog:all`. Для двух языков оформляйте блоки `<!-- changelog:ru --> … <!-- /changelog:ru -->` и `<!-- changelog:en --> … <!-- /changelog:en -->`. HTML-комментарии размещайте за пределами пунктов списка.
- Черновик создаёт и публикует workflow. После сбоя возобновляйте его для того же тега и оставляйте флаг **Set as a pre-release** выключенным.

Команды и настройка ключей приведены в [инструкции по выпуску](docs/releases.md).
