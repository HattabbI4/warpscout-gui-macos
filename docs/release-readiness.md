# Готовность к публикации / Release readiness

**27 ноября 2026 · GUI 1.0.3 · warpscout 0.17.0**

Исходники оболочки подготовлены для открытия под MIT. Публичный бинарный релиз с текущим ядром рекомендовано отложить до разбора предупреждений Go. **The source tree is prepared for publication. The bundled core still needs a security update or documented triage before distributing this ZIP.**

**Изменение в локальной сборке GUI 1.0.4 до первой публикации.** ZIP содержит только оболочку и инструкцию первого запуска. При отсутствии установленного ядра GUI загружает стабильный релиз напрямую из `vernette/warpscout`. Нижеследующая проверка относится к версии ядра 0.17.0, в том числе при отдельной загрузке. Для устранения риска необходимы исправления в запускаемом ядре либо разбор применимости предупреждений.

## Ядро

Проверялись официальные архивы `warpscout_0.17.0_darwin_arm64.tar.gz` и `warpscout_0.17.0_darwin_amd64.tar.gz` с SHA-256 из скрипта сборки. Бинарный режим govulncheck сообщил 35 уникальных бюллетеней для каждой архитектуры. Официальные сборки имеют флаги `-s -w`; результаты бинарного режима могут включать неиспользуемый код.

Дополнительно проверен тег `v0.17.0` (коммит `2b0ca53b93a7e2735bf7749c61ffcd3d4b080f75`) с Go 1.26.3, `CGO_ENABLED=0`, `GOOS=darwin`, `GOARCH=arm64`. В режиме анализа исходников govulncheck нашёл статические пути вызовов для **19 уникальных бюллетеней**. Для эксплуатации могут требоваться особые режимы клиента, сервера или окружения. Проверка не устанавливала возможность атаки на WarpScout.

Для повторной проверки нужны Go и govulncheck. В каталоге исходников ядра из указанного тега:

```sh
go install golang.org/x/vuln/cmd/govulncheck@v1.10.0
GOTOOLCHAIN=go1.26.3 CGO_ENABLED=0 GOOS=darwin GOARCH=arm64 govulncheck ./...
```

Для следующего кандидата возьмите исправленные бинарники или пересоберите ядро с обновлёнными Go и зависимостями. Повторите анализ, затем обновите контрольные суммы и уведомления о лицензиях, проверьте туннели, экспорт и SOCKS5. Версии в таблице взяты из базы Go на дату проверки. Актуальную сборку следует проверять заново.
